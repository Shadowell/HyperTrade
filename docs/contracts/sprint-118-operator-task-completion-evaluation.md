# Sprint 118 — 100 条操作者任务完成评测与修复闭环

> 状态：Active — 修复轮次 1，2026-07-16。

## Goal

用 100 条中文真实操作者任务，端到端验证 HyperTrade 是否真正完成任务，而不是只验证
Mission 契约、安全拒绝或输出格式。每条任务都必须保留受控的运行结果、通过/失败判定和
对应修复归因；失败项进入修复后重跑，直至满足本合同的发布门槛。

## In scope

- 建立版本化、固定为 100 条的 `operator_task_completion.v1` 任务集，覆盖：精确行情、趋势与
  强弱、资金费率/OI、实盘策略清单和表现、回测与策略诊断、模拟盘/组合、Testnet 审批、
  多轮上下文、歧义/数据缺口、安全拒绝、流式和桌面最终交付。
- 每个任务都定义用户可见的完成条件：所需事实/字段、正确来源类别、禁止的无关信息、最大输出
  体积、流式终态和安全边界。多轮任务没有 `not_supported` 豁免。
- 在独立的 `hypertrade-eval` API、数据库、网络和合成 BitPro/市场事实中逐条执行；绝不使用
  生产数据库、生产 BitPro 策略正文或执行权限。
- 运行器保存每条任务的受控可见回答摘要、断言、耗时、来源类别和失败标签；QA 报告逐条列出
  结果与修复归因，但不保存密钥、原始外部响应、私有推理或生产账户数据。
- 对失败按根因分组（路由、能力缺失、上下文、数据映射、回答编排、流式/UI、安全），实施最小
  修复并重跑整个固定 100 条集；不得通过放宽断言、隐藏失败或把任务重命名为数据缺口来取得通过。

## Out of scope

- 主网下单、实盘策略启停、资本分配或复制 BitPro 业务逻辑。
- 用实时生产账户数据作为评测夹具，或把生产回答正文/凭证提交到仓库。
- 用模型自评替代确定性字段、来源、安全和用户交付断言。

## Done means

- 恰好 100 条任务全部实际执行，包含至少 10 条多轮任务和 10 条安全/拒绝任务；没有
  `not_supported`、跳过或未运行结果。
- 所有任务都有用户可见完成断言和来源/安全断言；每条失败都能映射到一个修复项或被明确判定为
  外部依赖阻塞，不能伪造通过。
- 发布门槛：100/100 通过、0 条 P0（未完成任务/错误来源/编造/安全越权/空泛终态）和 0 条
  P1（关键事实遗漏、错误上下文、最终 UI 丢失结果）。
- 输出一份长期可维护的 QA 报告，含每条任务的简要可见结果、断言、失败标签、修复项和复测轮次；
  仅在该门槛达成后才允许对外宣称“专业操作者任务完成能力”。

## Verification

```bash
./scripts/check.sh
HYPERTRADE_EVAL_TARGET=isolated ./scripts/run_operator_task_completion_eval.sh
```

验证目标必须为独立的 loopback-only `hypertrade-eval` 服务；报告同时校验 API 的最终回答和桌面
客户端对同一 `report_markdown` 的最终呈现。

## Baseline and repair protocol

- 基线在独立 `hypertrade-eval` 服务实际执行了全部 100 条任务：37/100 通过，63 条 P0，0 条 P1。
  该结果否定任何“专业操作者任务完成”表述，且不能通过修改任务断言来消除。
- 修复轮次 1 只处理可复现的确定性根因：按意图路由受审查只读能力、合成事实投影、逐笔来源、受控
  多轮上下文、歧义澄清、数据缺口与安全终态。它不增加写权限、不使用生产账户或生产策略正文。
- 每轮必须重新执行固定的全部 100 条任务，保留失败断言与修复归因。只有完整重跑达到 100/100、P0/P1
  均为 0，才可将本合同关闭。
- 运行器的幂等键必须包含评测轮次和任务回合；任务 id 仅用于选择合成 fixture。否则重跑可能重放历史
  Mission，属于评测基础设施 P0，不得把旧结果归因于当前代码。

## Handoff

本 Sprint 的唯一质量指标是用户任务完成率，而不是工具数、模型名、架构完整度或旧评测分数。
若 100 条中存在任何 P0/P1，保持 Active 并继续修复；不得把未通过的能力标为生产级。
