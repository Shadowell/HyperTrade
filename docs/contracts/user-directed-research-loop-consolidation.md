## 切片 2：统一 CLI / BitPro 的 Paper 审核（已验证并部署）

- 新建 ARC 任务强制逐版本 Paper review，旧预授权参数不能绕过；历史任务可解码与查询。
- GET paper-review 与 POST paper-review/decide 共用候选代码、spec、回测/验证引用、条件和 Paper 配置哈希。
- 认证人类身份审核，签名绑定 paper 动作及 package hash；服务令牌不能批准。
- 状态领取在现有持久层串行，重复决定不重复外部操作，未知回执保留 effect_unknown，禁止盲重试。
- CLI research start/list/status/evidence/candidate/review/continue/decide 调用相同服务；BitPro 页面签名代理相同协议。
- 新协议 Paper 观察不再自动进入 Live 审批，原实例不被此次功能修改；NaN/Infinity/布尔指标不能作数值门禁依据。

验收：完整检查；候选通过后仍零 Paper 写；拒绝、篡改、过期签名、重复/并发领取及事件恢复回归；两端展示同一真实历史任务。
真实候选的人工批准不由验收脚本替用户执行。持久研究领取、AVO、独立样本外协议与 7+7 自动反馈仍按后续切片实现。

## 切片 3：有预算的 AVO 研究与恢复（已部署，真实失败路径已验收）

- 新任务默认 research_mode=avo；arc 模式保留为显式兼容入口，历史任务不自动重跑。
- 模型自主选择 inspect/propose/develop/finish/stop；通过现有 codegen 和 BitPro 做受约束的策略变异与实验，不开放运行时自修改或 Paper/Live 工具。
- 任务创建时冻结 119 天开发、1 天隔离、60 天最终验证窗口。模型只能读取开发实验反馈；最终窗口使用后不得追加预算继续调参。
- 最终验证基础默认值：净收益 >0、Sharpe >=0、最大回撤 <=20%、完成交易 >=30，均通过请求配置并在任务中冻结；不冒充完整 V2 稳健性认证，要求其他未实现策略时在模型调用前拒绝。
- 模型/工具/回测调用在派发前计入预算，派发前检查总时长；单次请求仍受 Provider/MCP 自身超时和传输重试规则约束。
- PostgreSQL session advisory lock 约束跨进程研究所有权；SQLite/内存仅承诺单进程开发互斥。
- worker 领取持久任务。模型输出丢失按剩余预算重新请求；已存在动作 ID 与代码指纹匹配的回执只补状态；未知工具副作用阻断重发。
- 预算追加覆盖候选、模型、工具、回测和时间；相同幂等键不重复追加，变更请求内容则拒绝。
- 验证后仍交付逐版本 Paper 审核包。代码或窗口变化使旧审核无效，读取新哈希不能绕过重新验证。

验收：真实模型选择工具并产生可追溯实验反馈；拒绝越权、重复标识、预算透支；崩溃恢复不重复回测；最终结果不进入迭代上下文；全量检查及上线读取验证。
真实 canary 限 2 候选、8 次 Agent 模型调用、3 次回测调用，不自动执行 Paper 审批。失败如实记录，不放宽门槛制造成功。
范围外：7+7 Paper 衰减触发、任意结构/规则重写、多资产组合和盈利能力认证，继续保留后续切片。

### 任务级 Provider 选择

新任务记录显式选择或 API 当前默认的 Provider。CLI start/continue 支持 --provider 与 --model（模型覆盖目前支持 codex/vide_coding），worker 使用任务中的选择，重启不依赖 API 进程的临时默认值。
更换仅允许在 needs_operator 且尚无候选时；同一幂等键不能改选不同 Provider。缺配置或计费拒绝时如实停止，不自动购买额度或静默修改全局模型。

### 切片 3 补验：预算语义与真实多轮修订

模型请求提供服务端当前总数、剩余额度、已计数候选 ID；当前请求预记入模型消耗，不再要求模型从工具历史重新计数。恢复旧任务时刷新预算说明，最终回测保留一个名额。
补验新建独立任务，仍限制 2 候选 / 8 次模型请求 / 3 次回测，复现已知开发失败后依据真实反馈修改参数并再次回测；不降低门槛，不批准 Paper。不把确定性测试序列冒充真实模型选择。

## 切片 4：Paper 7+7 退化与参数再研究

- 新建任务默认启用，可通过请求 feedback.enabled 关闭、feedback.threshold_pp 配置阈值；历史任务解码默认关闭，不追溯启动。CLI start 支持 --feedback-threshold-pp / --no-paper-feedback。
- 复用 BitPro paper_snapshot 与 strategy_return_series，只监控本系统已人工批准、身份匹配且运行中的不可变 Paper 会话。每天按已完成 UTC 日检查此前两个连续 7 天；14 天不足、会话/版本/成本变化、非正权益、缺少边界和超限间隔均只记缺口。
- 使用小时分桶权益计算净收益与窗口内峰谷回撤；允许边界误差不超过 1 小时、最大采样间隔默认 2 小时（可配置至 4 小时）。这是采样回撤，不宣称逐 tick 最大回撤。每 6 小时分段读取，共最多 56 份；上游原始样本超过每段 500 或存在未取完分页时拒绝，不截断、补点或拼接其他来源。
- 前 7 天净收益减最近 7 天净收益 >=10 个百分点，或最近回撤减前段回撤 >=10 个百分点，即触发；阈值可配置。金额 PnL 与累计 snapshot 收益不作周收益。
- 用 Paper 会话互斥锁与确定性子任务 ID 防并发/重启重复；子任务创建后关联失败可以恢复。已有子任务研究中、需人工处理、待审核或并行 Paper 运行时不重复触发；被拒绝或终止后最多下一 UTC 日重新检查。
- 新任务只允许原策略族/方向及原风险叠加下的参数变更，继承审核与资金边界，预算默认 3 候选 / 20 模型请求 / 8 回测，可通过 feedback.research_max_candidates / research_max_model_calls / research_max_backtests 配置。原 Paper 不暂停、不修改、不重置。
- 最终阶段保留两次回测，原代码与新候选使用同一冻结窗口及资金配置；收益/回撤至少一项改善且另一项不恶化，同时满足绝对门槛，才生成带原任务及比较回执的审核包。未知副作用停机核对。仍是基础同窗复验，跨代重叠窗口不构成新的统计独立性或盈利证明。
- 复用现有人工批准及独立 Paper 创建；不引入第二套审批或执行服务。CLI evidence 输出反馈、父子关联及比较；BitPro 活动流显示检查与子任务 ID。

验收：窗口/阈值/数据缺口、去重与创建中断恢复、同窗比较与审核阻断测试；完整 scripts/check.sh；生产原任务清点及只读接口核验。当前没有本系统已批准运行的 Paper，真实 14 天触发与人工批准后新旧并行需随实际会话积累验收，不制造 Paper 数据或代人工批准。

用户要求：默认 CLI/页面研究使用 Codex；修复资金约束和计数不更新，同时降低自主研究页面理解成本。

- 新默认 Provider 为 codex、模型 gpt-6-astra；显式 Provider 选择保留，历史任务不自动改选。生产仅更新这组非敏感配置，不修改认证凭据。
- 新编译策略默认1倍杠杆，以决策时净值20%计算单次目标保证金，配置上限2倍；显式名义金额也受该比例限制。回测和Paper共用同一代码，执行策略元数据进入审核哈希。
- 订单拒绝不更新持仓；后续Bar从Broker实际持仓重新对账，防止submitted后实际被拒绝留下虚假状态。
- BitPro回测执行层核对可用保证金、手续费和待成交预留；做空所得不成为可重复使用的现金。按实际请求杠杆记账，资不抵债停止回测，不把负权益后的反弹作为合格结果。
- 页面首屏围绕研究、审核、模拟运行展示下一步动作；开发实验结果独立展示，历史和技术细节折叠；计数取同一版本证据，过期异步响应不得覆盖新状态。
- 验证：两仓库单元/结构冒烟、构建检查与实际部署后页面发起真实回测。保留原Paper及历史数据，人工审批仍由用户执行。

最终验证复用同候选开发阶段已创建的 BitPro 策略 ID，并只读核对源码；不得再次创建同名策略。未知准备步骤经实际回执核对后可完成原待确认动作，不能无证据清空 pending 或重发回测。
