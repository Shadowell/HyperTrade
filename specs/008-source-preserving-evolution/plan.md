# 实现方案

沿用 ARC 生命周期、BitPro事实源、既有预算/审核/副作用账本，不另建研究执行器。

1. BitPro先交付 `strategy_research_source.v1` 只读合同，静态描述与执行验证分开；版本哈希覆盖研究有效输入，秘密与不可信执行不进入读取路径。实现与BitPro规格017独立维护。
2. 先消除原生/DB来源在Paper与回测解析上的分叉，再添加受控变体创建与明确参数政策。原生依赖留在BitPro，HyperTrade只持有引用、摘要和哈希；API形状在该切片落地前共同冻结。
3. BitPro在新候选创建与回测任务入队时保存不可变研究输入。校验来源、配置、参数、成本和资金；部署漂移、重复请求及未知结果均保留可追溯终态。
4. HyperTrade的evolution/AVO/self_test使用来源参数提案与变体工具。保持既有开发/最终窗口隔离、基线比较和人审；提案/去重/恢复/审核的身份从代码扩展为来源+配置+参数。
5. 复用readiness、告警与页面投影展示逐来源能力；真实清单清点后再按已验证能力扩大运行范围，不靠改配置掩盖未实现路径。

并行边界：来源描述服务、周期/基准读取修复（规格007）、诊断范围/读取原因修复（规格009）可独立开发；变体创建依赖来源合同，AVO接入依赖变体/不可变回测合同，真实验收依赖部署。文档只记录合同与验证状态，测试/生产原始输出保留在受控运行记录中。

验证重点：恶意顶层脚本不被GET执行；敏感键/值不泄露；标的或依赖变动使身份变化而运行游标不变；原生说明文本不当源码；同代码不同参数不误去重；排队后漂移不换实验；原资金/成本一致；原Paper身份及历史不丢失。
