# 来源变体候选引用同窗基线封存行情

状态：实施；2026-09-26；BitPro PR #960 已提供与 Paper 同构的固定预热（v3 绑定、`comparison_eligible=true`）。

## 背景
BitPro 要求来源变体候选回测必须引用基线的封存快照（`candidate_requires_baseline_data_snapshot`），但 AVO 开发阶段只跑候选、自测从不传快照参数；连接器只放行 v2 绑定，丢弃新 v3。另外自测幂等身份不含参数，同一父策略的所有变体共用创建键与回测键：第二个候选会被 BitPro 以同键异参拒绝，或复用第一个候选的回测结果。

## 需求
- FR-001：来源变体实验身份纳入父 manifest 与规范化参数差异；非变体身份不变。
- FR-002：候选回测前用与基线实验完全相同的创建/回测幂等键创建并回测同窗基线，取其唯一封存绑定的快照 ID/哈希交给候选；AVO 之后的基线自测重放同一任务。
- FR-003：基线无法给出唯一封存绑定时，候选失败关闭 `baseline_data_snapshot_unavailable`，不发起候选回测。
- FR-004：连接器放行 v2/v3 绑定并透传 `trade_start_ms` 与预热政策，仍不透传源码配置。

## 验收
流程测试证明基线先封存、候选引用其快照、不同参数候选键互异；失败路径不发起候选回测；旧代码下上述测试失败；v2/v3 连接器透传；完整检查通过。
